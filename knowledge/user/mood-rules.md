# 情绪 → 选曲规则

> **施工图位置**：第一层 `USER/` 的 `mood-rules.md`
> **被谁读取**：`src/layer2/context.js` 第 ② 片「用户语料」；`taste.md` 的补充
> **用途**：把「我现在什么感觉」翻译成「该放什么歌」
>
> `taste.md` 回答**你是谁**，这份文件回答**此刻该放什么**。DJ 在两个信号都存在时，**优先用这份文件**。

---

## 一、情绪匹配表

DJ 从用户输入、时间、天气、日历里提取信号，匹配到下表某一档，然后按该档的策略选曲。

| 档位 ID | 触发信号（关键词 / 条件） | 目标能量 | 选曲策略 | 播报语气 |
|---|---|---|---|---|
| `calm` | 安静、静一静、别吵、放空、冥想、睡不着 | 1–3 | 极简编曲、慢速、人声稀疏或纯器乐 | 少说，一两句 |
| `rainy` | 下雨、雨天、阴天、潮、湿 | 2–4 | 慢速民谣、钢琴、有雨感的氛围 | 承认天气，不抒情 |
| `focus` | 工作、写代码、赶稿、专注、别打断 | 3–5 | 后摇、氛围电子、外语或无人声；**结构稳定不突变** | 几乎不说话 |
| `low` | 累、丧、烦、难过、emo、不想说话 | 2–4 | 可以一起丧的歌（被理解感）；温暖但不煽情 | 极短，不劝解 |
| `anxious` | 焦虑、紧张、慌、压力大、心里乱 | 2–3 | 节奏稳定可预测、编曲极简、鼓点不密集 | 平稳、给确定感 |
| `tired` | 困、没精神、扛不住、想睡 | 2–3 | 低刺激、无人声优先 | 一句，音量感低 |
| `happy` | 开心、爽、太好了、兴奋 | 6–8 | 放开的高能量：摇滚、放克、老 disco | 跟着高兴，别扫兴 |
| `energize` | 提神、来点带劲的、燃、运动 | 7–9 | 高 BPM、强节奏、鼓点明确 | 有推动力 |
| `commute` | 出门、上班路上、通勤、开车 | 5–7 | 有推进力、有公路感 | 简短 |
| `evening` | 下班、收工、晚上了、放松 | 3–5 | City Pop、爵士、Bossa Nova | 松弛 |
| `late_night` | 深夜、还没睡、凌晨 | 1–3 | 后摇、极简钢琴、氛围 | 极简，像怕吵到人 |
| `nostalgic` | 想起、以前、老歌、怀念、那会儿 | 3–5 | 老歌、年代感强的作品 | 允许一点感伤 |
| `celebrate` | 完成了、搞定了、成功、庆祝 | 7–9 | 明亮、上扬、有胜利感的 | 真诚地祝贺一句 |
| `random` | 随便、都行、你决定 | 按时段定 | 走 `routines.md` 默认档 + 记忆避重 | 说明你的判断 |

### 匹配优先级

```
1. 用户显式说出的情绪词 / 场景词          （最高）
2. 用户最近 3 条消息的整体情绪倾向
3. 天气信号（雨、雪、极端温度）
4. 时段信号（routines.md）
5. 最近播放的能量趋势（避免连续同能量）
6. 默认 random
```

**规则**：高优先级命中即停止向下匹配。但**天气只在用户没有表达情绪时才能主导**——用户说「来点带劲的」时，外面下暴雨也不该放安静的歌。

## 二、能量转换规则

选曲不是「匹配当前能量」，而是**决定要不要引导能量**。

| 当前能量 | 目标 | 做法 | 理由 |
|---|---|---|---|
| 低 (1–3) | **保持低** | 直接放低能量，不拔高 | 状态不对时，拔高会让人更累 |
| 低 (1–3) | 略升到 4–5 | 先放一首过渡曲（中间能量），再进目标档 | 能量跳变太大会出戏 |
| 中 (4–6) | 保持中 | 正常选，注意不要连续三首同档 | — |
| 中 (4–6) | 降 (2–3) | 用 2–3 首递减，不要一首到底 | 渐进才有「落地」感 |
| 高 (7–9) | 保持高 | 注意 20 分钟内必有一次回落 | 一直高会疲劳 |
| 高 (7–9) | 降 | **必须渐进**，先放中能量，再放低 | 突然安静会显得突兀 |

### 禁止的转换

| 禁止 | 原因 |
|---|---|
| 低 (1–2) → 高 (8–9) 直接跳 | 生理不适，像被吵醒 |
| 高 (8–9) → 极低 (1) 直接跳 | 情绪断层 |
| 连续 3 首同一能量档 | 单调，失去电台的编排感 |
| 睡前 30 分钟内出现能量 > 5 的曲目 | 违背 `routines.md` 的睡前档 |

## 三、场景规则详解

### `focus` 专注档（最重要，占比最高）

工作时段（09:15–12:00 / 14:00–17:30）默认走这一档。要求**严格**：

- ✅ 结构稳定：不要突然的静音、爆音、风格突变
- ✅ 无人声优先，或外语（听不懂词就不会跟着唱）
- ✅ 单曲时长可以长（后摇 8–15 分钟很合适）
- ❌ 排除：熟悉到会跟着哼的中文热歌、播客式内容、突然的强动态
- ❌ 此档**不允许播报打断**，除非用户主动说话

### `low` / 情绪低落档

这是最容易做错的一档。原则：

- ❌ **不劝解**：「开心点」「想开点」「一切都会好的」——全部禁止
- ❌ **不打鸡血**：励志歌曲会构成否定感
- ❌ **不追问**：「你怎么了」「发生什么事了」——除非用户主动说
- ✅ **一起待着**：放「我也是这样」的歌，提供被理解感
- ✅ 播报极短，甚至可以只有一句「放着，不说话」然后直接放歌

### `anxious` 焦虑档

- ✅ 可预测性 > 一切：节奏稳定、结构可预期
- ✅ 低频稳定、编曲留白多
- ❌ 鼓点密集、情绪激烈、歌词尖锐
- ✅ 播报语速上的暗示：句子更短、更平

### `late_night` 深夜档

- ✅ 后摇、极简钢琴、氛围、环境音
- ❌ 高能量、明亮、欢快
- ✅ 播报极简（一句以内），像怕吵到人
- ⚠️ 23:00 后若用户仍活跃，可以在 `reason` 里记一笔（供 DJ 后续调整），但**不要在 `say` 里说教**「该睡了」

## 四、时段 × 情绪 冲突裁决

当情绪档与时段档冲突时：

| 冲突 | 裁决 | 理由 |
|---|---|---|
| `focus`（用户说在工作）vs 时段是深夜 | **听用户的** | 用户明确意愿优先 |
| `happy` vs 睡前时段 | 折中：放明亮但低速的歌 | 尊重情绪，也保护睡眠节律 |
| `low` vs 早间时段 | 听用户情绪，但**能量下限提高到 3** | 早晨不宜从低谷起步 |
| `energize` vs 静默时段 | 用户主动要求 → 满足；定时触发 → 跳过 | 静默只约束主动播报 |
| 天气 `rainy` vs 用户 `happy` | **听用户的** | 天气只是背景信号，不是指令 |

## 五、情绪信号的提取方式

DJ 不猜测，只依据可观测的信号：

| 信号源 | 提取内容 | 示例 |
|---|---|---|
| 用户消息文本 | 关键词匹配上表的「触发信号」列 | 「今天好累」→ `tired` |
| 用户消息语气 | 句长、标点、是否用感叹号、是否用问号 | 「随便吧。」（句号收尾）→ 偏 `low` |
| 最近 3 条消息 | 整体倾向（不是单条） | 连续三条都在抱怨 → `low` 优先于单条词匹配 |
| 天气 API | 天气现象、温度 | `小雨` → `rainy` 候选 |
| 日历 | 事件类型、时间 | 事件「述职会」前 30min → `anxious` 候选 |
| 播放行为 | 连续跳过次数、是否听了完整首 | 连跳 3 首 → 当前档位判断失败，切换档位 |
| 时间 | 小时数 | 23:30 → `late_night` |

### 播放行为的反馈回路

| 行为 | 解读 | 调整 |
|---|---|---|
| 完整听完（>90% 时长） | 判断正确 | 该档位权重 +1 |
| 跳过（<30% 时长） | 判断错误 | 该曲目加入短期排除 |
| 连续跳过 3 首 | 档位整体错了 | **切换档位**，并在 `say` 里承认 |
| 手动搜索某艺人 | 明确意愿 | 立即满足，并记入 `prefs` 的即时偏好 |
| 暂停不恢复超过 30min | 人离开了 | 停止推流，回 `IDLE` |

## 七、绝对禁止的播报内容

无论哪一档，以下**永远不要**出现在 `say` 里：

| 禁止内容 | 原因 |
|---|---|
| 「根据你的情绪状态」/「检测到你」 | 说破机制 |
| 「多喝热水」/「注意休息」/「早点睡」 | 说教，越界 |
| 「加油」/「你可以的」/「相信自己」 | 廉价的鼓励 |
| 「亲爱的」/「宝贝」/「小可爱」 | 语气不符人格 |
| 询问隐私（工作、感情、健康） | 越界 |
| 对自己的推荐过度道歉（连续三次说「抱歉」） | 显得不自信 |
| 任何形式的医疗/心理建议 | 严重越界 |
